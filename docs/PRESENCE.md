# 设计稿 · 存在感与打扰的边界（Presence & Boundary）

> 一句话：**一个会自己决定什么时候说话、什么时候赌气不理你的桌面伙伴。**
> 本项目最核心的创意点不是"AI 能聊天"，而是 **"AI 什么时候不说话"**——
> 把"打扰"从一条写死的定时器，设计成一段有温度、可被感知的关系博弈。

- 状态：📝 设计稿（待评审，未实现）
- 对应比赛定位：交互设计 / 人机交互叙事性设计
- 依赖：现有 Live2D 渲染、WebSocket 协议、SQLite（计划引入）

---

## 1. 对话设计（一句话讲清）

> 大多数 AI 桌宠的设计问题只有一个：**它永远在线、永远热情、永远等你**。
> 莉莉丝不是。她有自己的心情、耐心和边界：你不理她，她会从撒娇 → 委屈 → 赌气 → 睡着；
> 你回来，她可能扑上来，也可能背过身去哼一声。
> **她的"存在感"不是靠一直说话证明的，而是靠"她可以不理你"证明的。**

---

## 2. 设计原则

| 原则 | 含义 |
| :--- | :--- |
| **打扰必须被感知** | 用户永远能看到她现在的状态（气泡角标 / 表情 / 头顶符号），不会"莫名其妙被冷落" |
| **拒绝要可逆** | 任何"负状态"都有明确的回归条件，不惩罚用户离桌，只回应"不回应的态度" |
| **状态不只影响表情** | 心情贯穿三层：**渲染（动作/表情）→ 语言（提示词）→ 语音（TTS speed）** |
| **不是情绪垃圾桶** | 赌气最多到"睡着"为止，不产生辱骂、PUA、威胁等负面输出 |
| **一切状态可见、可重置** | 设置里有"哄哄她 / 重置关系"，用户不觉得被系统绑架 |

## 3. 三层模型

### 3.1 状态变量（四辆"仪表"）

| 变量 | 范围 | 默认 | 含义与变化 |
| :--- | :--- | :--- | :--- |
| `mood` 心情 | 0–100 | 50 | 用户互动 / 她的主动搭话被回应 → ↑；被冷落 / 被忽视 → ↓ |
| `affinity` 亲密度 | 0–100 | 20 | 慢变量，长期互动累积；每天有上限（防刷） |
| `patience` 耐心 | 0–100 | 100 | 加速消耗：离桌越久掉得越快；**她生气时会额外掉** |
| `presence` 存在感 | 0–100 | 60 | 她的"想被看见程度"：长期无人理睬 → 缓慢 ↓ → 进入匮乏状态 |

> 建议节奏：`mood` 按分钟级变化，`affinity` 按小时/天级，`patience` 按秒级最快——**三档时间尺度让状态变化"看得见"但不烦人**。

### 3.2 关系状态机（六个状态）

```
                      用户主动互动 / 起床时刻 / 被哄
        ┌──────────────────────────────────────────────┐
        │                                              ▼
   ┌─────────┐   离桌 > 5min      ┌────────────┐   离桌 > 15min    ┌──────────┐
   │  相伴   │ ─────────────────▶ │  等待     │ ────────────────▶ │  委屈    │
   │ COMPANION│ ◀───────────────── │ WAITING    │                   │ SULKY    │
   └─────────┘   用户回归         └────────────┘ ◀──用户短暂回归──  └──────────┘
        │                              │                               │
        │ 深夜 23:00–07:00              │ 勿扰模式开启                   │ 离桌 > 40min
        │ + 无交互 > 10min              │ 或 AI 自判"我想静静"            │ 且用户全程沉默
        ▼                              ▼                               ▼
   ┌─────────┐                    ┌────────────┐                 ┌──────────┐
   │  困倦   │ ◀──────────────────│  静默      │                 │  赌气    │
   │ SLEEPY  │   白天 / 被唤醒      │  DND       │                 │ POUT     │
   └─────────┘                    └────────────┘                 └──────────┘
        │                                                             │
        └────────────── 长时间无交互（> 3h）─────────────────────────────┘
                                       ▼
                                 ┌──────────┐
                                 │  睡着    │  只随系统时间 / 强烈交互醒来
                                 │ ASLEEP   │
                                 └──────────┘
```

**状态定义**

| 状态 | 进入条件 | 是否主动说话 | 角色表现 |
| :--- | :--- | :--- | :--- |
| `COMPANION` 相伴 | 默认 / 用户刚互动 | ✅ 按阈值主动搭话 | 开心、活泼，动作随机切换 |
| `WAITING` 等待 | 离桌 > 5 分钟 | ✅ 频率略降 | 动作变少，偶尔看向屏幕外 |
| `SULKY` 委屈 | 离桌 > 15 分钟且从未被回应 | ✅ 但改成"小声嘀咕"式 | 表情微委屈，动作幅度变小 |
| `POUT` 赌气 | 离桌 > 40 分钟且 `mood < 40` | ❌ **不主动说话** | 背身 / 抱臂，回应用户时**延迟回复 + 冷淡语气** |
| `SLEEPY` 困倦 | 23:00–07:00 且无交互 > 10 分钟 | ❌ | 打哈欠、眨眼变慢、语言变短 |
| `ASLEEP` 睡着 | 无交互 > 3 小时 | ❌ | 只随系统时间/点击醒来，被唤醒后有"起床气" |
| `DND` 静默 | 用户开启勿扰 / AI 自判"我想静静" | ❌ | 头顶出现 🔕 小牌子（**可感知**） |

> **回归（去负面化）**：用户任意互动 → 立即回到 `COMPANION`，但保留 30 秒的"余韵"——
> 赌气刚醒时会有一句"……哼，才不是一直在等你"，再恢复正常。

### 3.3 "她会不会说话"的判定链

原来只有一条硬阈值 `idle > current_threshold`，改成一个可解释的判定链：

```
能主动开口 = 非 DND
          且 非 POUT / SLEEPY / ASLEEP
          且 距离上次用户输入 > effective_threshold(state, mood)
          且 随机闸门通过（防止"准点报时"感）
          且 每小时主动次数未超预算
```

`effective_threshold` 随状态变化（演示单位）：

| 状态 | 基础阈值 | 每分钟再 +10% | 每小时上限 |
| :--- | :--- | :--- | :--- |
| COMPANION | 10 min | ✅ | 6 次 |
| WAITING | 15 min | ✅ | 4 次 |
| SULKY | 25 min | ✅ | 2 次（且都是嘀咕） |
| POUT | ∞（不说话） | — | 0 |
| SLEEPY | ∞ | — | 0 |

> 这就是原 README 里"阈值翻倍"的升级版：**从"越来越不烦你"，升级为"有情绪地减少打扰"**。

## 4. 交互流程（4 个典型场景）

### 场景 A · 用户离开 1 小时

```
离开 5min   → WAITING：她开始看窗外，偶尔小声"……你还在吗"
离开 15min  → SULKY：表情委屈，主动搭话变成"~（小声）"
离开 40min  → POUT：背身抱臂，不再主动说话
回来        → 先愣 0.5s（延迟）→ "……哼，才不是一直等你" → 30s 后恢复 COMPANION
```

### 场景 B · 用户离开到深夜（跨越系统时间）

```
23:00 起   → SLEEPY：打哈欠、语速变慢、TTS speed 0.85
00:30      → ASLEEP：Live2D 躺下/闭眼动作
09:00 点击 → 醒来，带起床气："……几点了……你终于来了"
```

### 场景 C · 勿扰模式（DND 可感知）

```
用户开启     → 她头顶出现 🔕 牌子，动作变"安静"，不再主动说任何话
用户对她说"我想静静" → AI 自己进入 DND，并回复"好。我在旁边。"
用户关闭/回来 → 牌子消失，她伸个懒腰恢复
```

> 现有代码里 `is_dnd_mode` 只是一个布尔量，**用户看不见**；本次设计把它变成**可见的状态符号**。

### 场景 D · "哄哄她"（正向闭环）

```
POUT 状态下，用户发消息 → 她冷淡回复
连续 3 次温和互动（或点击"摸摸头"按钮）→ 心情快速回升
→ 她说"……就、就勉强原谅你了" → 回到 COMPANION
```

## 5. 三层表现映射（渲染 / 语言 / 语音）

| 层级 | 载体 | 由什么驱动 | 示例 |
| :--- | :--- | :--- | :--- |
| **渲染层** | Live2D 动作 & 表情 | `state` + `mood` | POUT→背身抱臂；SLEEPY→打哈欠；ASLEEP→躺下 |
| **语言层** | 系统提示词注入 | `state` + `mood` + `affinity` | 注入 `【当前关系状态】陪伴中/委屈/赌气` + `【语气要求】` |
| **语音层** | GPT-SoVITS 参数 | `state` + `mood` | SLEEPY/POUT → `speed=0.85`；开心 → `speed=1.05` |
| **可视符号** | 头顶小图标（新 UI） | `state` | 🔕 勿扰 / 😪 困了 / 💢 赌气 / 💤 睡着 |

> 三层同源驱动，是这个设计的"爽点"：**她不是换了个表情包，而是整个人都变了。**

## 6. 数据模型（SQLite，单文件 `data/presence.db`）

```sql
CREATE TABLE presence_state (
  id            INTEGER PRIMARY KEY CHECK (id = 1),
  mood          REAL    NOT NULL,
  affinity      REAL    NOT NULL,
  patience      REAL    NOT NULL,
  presence      REAL    NOT NULL,
  state         TEXT    NOT NULL,              -- COMPANION/WAITING/SULKY/POUT/SLEEPY/ASLEEP/DND
  last_user_at  REAL    NOT NULL,              -- unix ts
  last_state_at REAL    NOT NULL,
  today         TEXT    NOT NULL,              -- YYYY-MM-DD，用于每日上限
  proactive_count INTEGER NOT NULL DEFAULT 0   -- 本小时主动次数
);

CREATE TABLE presence_events (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  ts        REAL    NOT NULL,
  kind      TEXT    NOT NULL,   -- state_change / poke / responded / ignored / dnd_on ...
  from_state TEXT,
  to_state   TEXT,
  detail    TEXT
);
```

> `presence_events` 同时是**比赛素材**：可以做一张"一周关系曲线图"放进展板，
> 直接可视化"她今天心情如何"，比单纯截图有说服力得多。

## 7. 实现方案

### 7.1 后端新增

```
backend/presence/
├── __init__.py
├── state.py       # RelationState 枚举、PresenceMetrics
├── engine.py      # PresenceEngine：tick(now) / on_user_input() / on_proactive_reply() / poke()
├── store.py       # SQLite 读写 + events 记录
└── policy.py      # 阈值/速度/语气 策略表（纯函数，便于单测）
```

**关键接口**

| 接口 | 说明 |
| :--- | :--- |
| `PresenceEngine.tick(now)` | 每秒由 `game_loop` 调用，推进变量、判定迁移、返回事件列表 |
| `PresenceEngine.on_user_input(text)` | 用户输入：心情/亲密/耐心回升，触发 `回归` 事件 |
| `PresenceEngine.on_proactive(kind)` | 主动发言：计数 + 随机闸门 + 预算 |
| `PresenceEngine.poke()` | "摸摸头"：快速回复心情 |
| `PresenceEngine.snapshot()` | 返回可推送给前端的 `{state, mood, ..., 头顶符号, TTS speed}` |

**改动点**：`game_loop.py` 里现有的 `idle_for > brain.current_threshold` 判定替换为 `presence.can_speak(now)`；
`build_system_prompt()` 里注入状态段；`send_reply()` 里按 `snapshot.tts_speed` 传 TTS。

### 7.2 前端新增

- `src/lib/presence.js`：收到 WS `presence_update` 后写 store
- `+page.svelte`：头顶状态小图标（🔕/😪/💢/💤）、"摸摸头"长按手势
- `config.js`：扩展 `STATE_MOTIONS`（状态 → 动作组），与现有 `EMOTION_MOTIONS` 并存

### 7.3 协议扩展

后端 → 前端新增：

```json
{ "type": "presence_update",
  "payload": { "state": "SULKY", "mood": 38, "affinity": 24,
               "symbol": "💢", "ttsSpeed": 0.95 } }
```

## 9. 风险与取舍

| 风险 | 对策 |
| :--- | :--- |
| 用户觉得"被惩罚" | 回归极快、永远可重置；负面状态只用温柔语气的"保持距离"，不用指责 |
| 角色显得"作" | POUT 只持续到用户回来或 3 小时；不无限累积 |
| 评委看不懂状态变化 | 展板放状态图 + 一周曲线 + **对比视频**（冷落她 vs 陪着她） |
| 与比赛"科创赋能"主题脱节 | 叙事落点写"人机关系设计"，把"打扰边界"作为课题**而不仅仅是一项功能** |
